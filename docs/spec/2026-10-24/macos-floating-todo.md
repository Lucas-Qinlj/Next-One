## 1. 目标与使用场景

许可要求（2026-10-26 用户确认）：项目采用 PolyForm Noncommercial License 1.0.0，仅授权条款允许的非商业用途，不授权商用。根目录 LICENSE 与 NOTICE 为准，后续应用及分发的 Skill 携带两份文件；不将本项目描述为允许自由商用的开源软件。

产品方向补充：用户确认以 `neo` 作为 Coding Agent 中的显式入口，先降低 Skill 选择成本，再通过自然语言完成待办操作，覆盖项目与生活事项。用户的产品判断、入口规则和验收见 [neo 快捷入口](../2026-10-26/neo-shortcut.md)。

用户经常只在 Codex 中讨论正在做或以后要做的功能，没有时间再打开独立软件录入待办；已有待办又不容易一直显示在明显的位置。

本项目提供一份用户与 Codex 都能读写的本地待办数据，以及可常驻屏幕的悬浮清单。目标是让明确的工作事项在对话过程中被及时保存，在后续工作中重新被读到，而不是遗留在聊天记录中。

典型场景：用户说“先实现悬浮球，透明度后面再做”，Codex 在已启用工作规则的会话中关联或创建两个任务，实施时更新状态；用户直接在屏幕上的清单查看、补充描述或修改优先级。

本 Spec 是产品与工程边界；ASCII 保留原设计，实际实现与验证以第 13 节和验收报告为准。

## 2. 需求来源与假设

### 2.1 用户明确提出的需求

| 编号 | 需求 |
| --- | --- |
| R01 | Codex 可以按用户要求管理 Todo，与用户共享近期待办上下文 |
| R02 | 项目通过本地路径绑定，采用简单方式 |
| R03 | 提供 Skill，指导 Codex 调用 Todo 的本地接口 |
| R04 | Todo 支持优先级 |
| R05 | 支持子 Todo、逐级展开收起和自定义颜色，最多十层 |
| R06 | Todo 包含标题、描述、截止时间、创建时间；描述可包含文本、图片和视频 |
| R07 | 屏幕悬浮球单击展开/收起小窗口；一个角贴住球，其余三个角可调整大小；按住球可移动球和窗口 |
| R08 | 窗口支持置顶和一定程度的透明，设置页可调透明度 |
| R09 | 置顶下可锁定；锁定时面板不接收点击，事件穿透至背后应用，球继续可操作 |
| R10 | 界面简洁、简单；Codex 可记录正在进行及后续规划的明确事项 |

### 2.2 本方案的建议默认值

以下为上一轮方案的具体化，作为实现规划依据；不能表述为用户已经逐项确认。

- 单人、单机、本地优先，不需要账号、云同步或应用内模型调用。
- 使用 SwiftUI + AppKit + SQLite；本地接口先采用 CLI，不引入 HTTP 服务或 MCP 服务。
- 状态采用待办、进行中、已完成；优先级显示为紧急、比较紧急、一般，分别对应 high、medium、low，默认 low（一般，2026-10-27 用户调整，仅影响新建任务）。
- 截止时间允许为空；支持仅日期和具体时间两种精度。
- 首版描述采用多行文本和附件区，不做复杂富文本编辑器。
- 颜色采用有限预设色和无颜色，不以颜色代替状态/优先级。
- 默认调整面板背景透明度，文字与球保持清晰；整窗含文字透明属于待决策项。
- 右键悬浮球提供解锁入口，菜单栏入口可作为隐藏或位置异常时的恢复入口。
- 不自动完成父任务；存在未完成子任务时，完成父任务需明确是否一并完成。

| 模块 ID | 职责 | 依赖 |
| --- | --- | --- |
| `todo-core` | 项目绑定、任务树、状态、优先级、颜色、时间、附件、事务与校验 | 无 |

先用临时数据验证窗口交互，再建立 `todo-core`，连接完整 UI，最后接入 CLI 和 Skill。窗口试验不构成数据能力或整个产品的交付完成。

首版不包含：多人协作、账号体系、云端同步、网页端、自动扫描所有 Codex 聊天、内置聊天机器人、自动执行 Todo、日历同步、重复任务、截止通知系统或复杂富文本。截止时间用于显示和排序，不等于已承诺系统提醒。

安装 Skill、修改持续工作规则、启用登录启动属于另行授权的用户操作；本轮本地实现未执行这些动作。

## 4. 数据与业务规则

### 4.1 项目

- 项目保存稳定 ID、显示名称和可选绑定的绝对目录路径；可先仅填名称创建，再绑定目录。通过目录创建时名称默认取目录名，允许修改。
- 保留“未分类”，用于不属于项目的任务；“全部项目”是查询范围，不是可写入的项目。
- 使用目录选择器绑定，只记录路径，不复制、索引或上传项目代码。
- 将路径规范化后，按真实目录边界匹配；`/work/app` 不得匹配 `/work/apple`。当前目录位于项目下时也可命中，嵌套绑定选择最长匹配。
- 同一路径不得属于两个项目。Git worktree 可由用户显式补充为同一项目的另一个绑定路径，不凭仓库名称或相似路径自动合并。
- 目录移动或暂时不存在不删除项目或任务，显示失效状态并允许重新绑定。每条绑定路径的重绑按钮旁提供 trash 图标解除绑定，确认框明确只解除关联，保留项目、待办与磁盘文件；最后一个目录也可解除，之后可重新绑定。操作校验项目 revision，过期请求失败不覆盖新绑定。
- 未匹配到项目时不得静默写入其他项目：查询可返回未匹配，写入需明确指定项目或未分类。

### 4.2 Todo 对象

| 字段 | 含义与要求 |
| --- | --- |
| `id` | 稳定唯一 ID，创建后不因改名或移动改变 |
| `project_id` | 所属项目；为空表示未分类 |
| `parent_id` | 父 Todo ID；根任务为空 |
| `title` | 必填，去除首尾空白后不可为空 |
| `description` | 多行文本，可为空 |
| `status` | `todo`、`in_progress`、`done` |
| `priority` | `high`、`medium`、`low` |
| `color` | 预设颜色标识或无颜色 |
| `due_date / due_at` | 日期型或时间型截止值，互斥，允许均为空 |
| `created_at` | 自动记录，不可通过普通更新改写 |
| `updated_at` | 成功修改时自动更新 |
| `completed_at` | 完成时记录；重新打开时清空 |
| `source` | 创建来源：用户或 Codex；不随后续编辑改写 |
| `revision` | 并发更新检查所需版本 |

时间型时间戳统一存储为明确时区的时间点，界面按用户本地时区显示。仅日期的截止值保持日历日期语义，避免时区转换改变日期。创建来源不是执行或验收证据。

### 4.3 层级、状态与排序

- 每条 Todo 使用软件当前存储内所有未删除任务全局唯一的短编号（A1…Z9、AA1…），用于界面显示与 CLI/对话精确引用；归档后可复用，恢复重新分配，写入使用查询返回 UUID，详见[归档规则](../2026-10-26/archive-completed.md)；项目标题数量统计该分区完整任务树，详见[全局任务短编号与项目数量](../2026-10-26/task-short-codes.md)。
- 根 Todo 为第一层，最多十层。新增、移动整个分支和 CLI 写入均应用相同限制。
- 禁止自己作为父节点、循环引用、缺失父节点及跨项目父子关系。
- 子任务默认继承所属项目；优先级和颜色独立设置，不隐式传播父任务修改。
- 移动到另一项目时以完整分支为单位原子更新，避免出现部分子任务仍在原项目。
- 有子任务的条目独立展开/收起；收起不改变状态或丢失内容。展开状态属于界面偏好，不属于待办完成状态。
- 父任务显示直接子任务的完成数，例如 `1/3`；不混算所有后代。
- 存在未完成后代时，完成父任务需要明确选择“一并完成”或取消；不得静默批量完成。
- 子任务全部完成不自动完成父任务，允许保留验收工作。已完成父任务下新增或重新打开未完成任务时，同一事务将必要祖先恢复为待办，并在结果中说明。
- 未手动排序的同级任务默认按优先级、截止时间、创建时间排序；拖动后以持久化手动顺序优先，不打散任务树，进行中使用状态标识。详见[拖动排序与项目合并](../2026-10-25/task-drag-grouping.md)。
- 已完成根任务统一在底部默认收起；未完成父任务的已完成子任务仍在父级下以折叠区域查看。底部计数按当前查询范围的已完成根任务计算，不重复计算后代，不因展开状态改变。详见[统一已完成区域](../2026-10-26/unified-completed.md)。
- 删除有子任务的对象时展示影响范围，按整个分支处理。建议采用可恢复删除，明确恢复入口，具体保留期在实现前确定。

### 4.4 描述与附件

- 描述区支持文字输入、图片粘贴、图片/视频文件选择和拖入。
- 导入时复制附件到应用管理的本地目录，记录稳定附件 ID、任务 ID、原文件名、媒体类型、字节数及存储位置；数据库不存大型媒体二进制。
- 图片显示缩略图，视频显示缩略图或文件信息，点击打开预览；不可预览时给出可理解反馈，不让任务不可编辑。
- 原文件删除或移动后仍能读取已成功导入附件。导入中断、磁盘不足或格式不支持时明确失败，不留下假成功记录。
- 附件格式、大小上限及预览兼容范围在实现前确定并显示于必要的导入反馈，不承诺任意视频编码均可播放。
- 删除任务或附件必须考虑恢复与文件引用，不直接清理仍被有效记录使用的文件。

## 5. 窗口与交互

### 5.1 悬浮球与锚点

- 悬浮球与面板使用独立窗口，保持位置联动；球本身保持可交互。
- 悬浮球的显示层级始终高于任务面板，重叠处由球覆盖面板；点击/编辑面板、打开设置、展开收起及切换置顶/锁定均不得反转两者层级。此规则依据 2026-10-25 用户遮挡截图补充，不表示覆盖系统安全提示。
- 单击球切换面板展开/收起。按住拖动超过小距离阈值后按移动处理，不在松开时误触单击。
- 即使焦点在其他应用或清单窗口，悬浮球也应接收首次按下并直接拖动，不要求先点击聚焦。展开、收起和锁定状态均适用。
- 面板一个角紧贴球形成锚点，拖动球时两者一起移动。
- 顶部工具栏空白区域（含上下留白）也支持首次按住拖动，超过 4 pt 后球与清单一起移动，松手不折叠清单；项目选择器和操作按钮保留原有行为。锁定穿透时顶部不接收输入。适用于清单、详情、设置和回收站共用顶部。
- 三个非锚定角保留拖拽缩放命中区，不显示角落图标；悬停时提供缩放光标。锚点保持不动；对角调整宽高，相邻两个角按锚点约束调整相应维度。此处依据 2026-10-25 用户截图反馈更新。
- 缩放光标必须为与操作轴一致的双向箭头：单宽度角为左右、单高度角为上下、双维度对角为对应的斜向箭头（左上—右下或右上—左下），随展开方向切换；不使用十字光标。继续保留固定锚点几何约束，不增加常驻角落图标。
- 根据屏幕可用区域选择展开方向，靠边时避免溢出；拖动过程中避免反复翻转方向。
- 设置合理最小尺寸，窄窗口标题省略、列表纵向滚动；详情可查看完整标题与父级路径，十层缩进不得使任务完全无法操作。
- 应用内容区所有纵向/横向滚动条统一为 3 pt 细滑块、不绘制粗轨道，包含清单、详情、描述编辑区、设置和回收站；保留原生拖动命中范围、滚轮及键盘滚动，不修改系统滚动条偏好。依据 2026-10-25 用户“所有滚动条都调细”的要求。
- 保存球位置、面板尺寸和锚定方向；显示器断开或分辨率变化后恢复到可见区域。

### 5.2 置顶、透明与锁定

| 状态 | 面板输入 | 面板层级 | 悬浮球 |
| --- | --- | --- | --- |
| 收起 | 不显示 | 不适用 | 可单击展开、拖动和右键 |
| 普通展开 | 可编辑、滚动、缩放 | 普通窗口 | 可操作 |
| 置顶展开 | 可编辑、滚动、缩放 | 普通应用窗口之上 | 可操作 |
| 锁定展开 | 鼠标事件穿透，不接受键盘输入 | 保持置顶 | 可操作，显示锁定标记 |

- 锁定只适用于置顶状态；未置顶时隐藏或禁用锁定入口，并提供简短解释。
- 进入锁定前结束编辑并释放键盘焦点；有保存失败时先反馈，不能让未保存内容悄然丢失。
- 锁定面板不接收点击、双击、右键、滚动或拖动，也不能缩放。输入由系统交给背后应用，不由本应用合成重发。
- 锁定期间 Codex 更新仍刷新显示，不能抢回键盘焦点。
- 右键球提供“解除锁定”；单击球仍只负责展开/收起。收起再展开保留当前锁定状态；建议应用重新启动后不自动恢复锁定，避免找不到编辑入口。
- 解锁后保留置顶。取消置顶必须先退出锁定，不能遗留不可交互状态。
- 设置页提供背景不透明度 0%–100% 调节，默认 90%，保存后重启保留（2026-10-26 用户确认最低值由 30% 改为 0%）。0% 时背景完全透明，文字与悬浮球仍保持不透明。建议首版调背景，保留文字与球的可读性；支持系统提高对比度/减少透明效果的可用性需求。
- 置顶目标是普通应用窗口，不以覆盖锁屏、系统安全提示或所有全屏内容为验收要求。
- Spaces、全屏应用、Stage Manager 和多显示器行为按实际支持范围验证并记录，不由单一窗口属性推断全部兼容。

### 5.3 编辑与反馈

- 页面样式以“待办详情”为基准：根视图统一中性普通按钮、13 pt 正文和小尺寸控件，设置/详情/回收站采用一致的 14 pt 横向、12 pt 纵向内容边距；输入框使用淡色圆角背景。保存操作可用蓝色、危险操作可用红色；不再使用全局绿色强调色影响设置等普通操作。
- 清单只保留项目选择、置顶、锁定、设置、任务树和快速添加入口。
- 快速添加默认收起，仅显示右下角加号。点击后以右下角为固定原点，约 0.42 秒向左/向上逐渐扩展为项目归属与标题输入区，收起反向缩回；不得瞬间切换。展开结束聚焦标题；添加成功后清空并缩回，失败保留输入与展开状态。不显示收起叉按钮；点击添加区域外或面板失去键盘焦点时收起，Escape 也可收起；标题及归属草稿在本次会话保留，再展开继续编辑。新增子任务入口使用同一输入区并明确父任务，锁定时不可操作。减少动态效果时缩短动效。依据 2026-10-25 用户添加入口动效及后续去掉叉按钮的要求。
- 空清单说明在清单可用区域内水平、垂直居中；标题 14 pt、说明 12 pt，图标缩至 28 pt，不使用大号空状态组件。添加区展开/收起后仍按剩余清单区域居中。
- 快速添加展开区按实际内容紧凑排布，顶部内边距 6 pt，禁止固定高度配合底对齐制造额外空白；加号图标从默认约 13 pt 改为 26 pt（视觉两倍），点击区域 44×44 pt。展开高度 72 pt，标题输入与加号垂直中心对齐。依据 2026-10-25 用户顶部留白及加号尺寸纠正。
- 顶部项目选择器靠左对齐，不在固定宽容器中居中；任务行不为不存在的展开按钮预留空列。清单与快速添加区使用一致的左右边距；“添加到”与项目选项使用相同字号。
- 所有非阻断操作提示统一在面板底部以浮层缓缓上滑出现，覆盖现有组件，不参与列表或底栏布局；成功绿色、错误红色、提醒黄色，并配语义图标和文字。每次提示 3 秒后自动消失，最右侧叉按钮可立即关闭；新事件替换当前提示并重新计时，旧计时不能关闭新提示。确认删除/级联完成等需要用户选择的对话框保留，不改为自动消失的提示。
- 点击标题在同一面板打开详情，返回时保留列表位置。勾选状态与打开详情的点击目标明确区分。
- 详情页仅在存在祖先时显示父级路径；根任务不保留空路径占位。标题贴近内容区顶部，状态/优先级/颜色和截止采用提醒事项风格的横向属性行，左侧图标与名称、右侧选择器，按 6.1.2 的圆角分组规范展示。普通操作使用中性按钮，删除使用红色；详情自动保存，不显示保存、读取按钮或已保存占位。此项依据 2026-10-25 详情截图反馈。
- 快速添加成功后进入列表，失败时保留输入。详情建议自动保存，但界面需区别保存中、已保存与失败，切换页面或锁定前不得丢失未保存内容。
- 右键任务提供新增子任务、修改优先级/颜色、移动及删除等对象操作。
- 设置页提供项目绑定管理、透明度及 Codex 接入。安装 Skill 和工作规则前展示将修改的位置及内容；保留已有规则，不覆盖整个配置文件。
- 登录启动、所有桌面显示是建议配置项，默认值待实现前确认，不在未授权时修改系统设置。

### 6.1.1 全部项目分组与优先级标签（2026-10-25）

- 来源：用户确认“全部项目”下按绑定项目分组，透明框内只显示细彩色边框，点击项目名称折叠；优先级使用三种圆角底色白字标签。

## 7. Codex 本地接口与工作规则

### 7.1 接入结构

```text
用户 -> SwiftUI 界面 -----> 共享业务规则 -----> SQLite + 附件目录
Codex -> Skill -> CLI ----> 共享业务规则 -----> 同一份本地数据
```

- CLI 是首版本地接口，不需要监听网络端口。应用关闭时仍可读写；下次打开显示最新数据。
- 界面与 CLI 复用校验和事务逻辑。运行中的应用观察外部写入并刷新，不因刷新覆盖正在编辑的字段。
- 查询以结构化 JSON 返回，写入返回对象 ID、新版本及明确成功/失败；错误返回非零退出码和稳定错误代码。
- 更新支持预期版本检查，发现其他入口已修改时返回冲突，不直接覆盖。创建支持请求幂等键；同一请求重试返回原结果，不仅依赖相似标题去重。
- 父子批量状态和分支移动以事务完成；失败不能留下部分已完成或部分已迁移数据。
- 核心错误至少区分：项目未匹配、对象不存在、非法字段、层级超限、循环引用、版本冲突、附件失败和存储不可用。

### 7.2 拟定命令面

以下保留最初接口方向；实际完整参数与错误结构已落实在 CLI 帮助及 [接口参考](../../../Skills/next-one/references/cli.md)。

```text
todo project list --json
todo project bind --path <目录> --name <名称> --json
todo context --cwd <当前目录> --json
todo list --project <项目ID> --json
todo get <任务ID> --json
todo add --project <项目ID> --title <标题> --priority high --json
todo add --parent <任务ID> --title <标题> --json
todo update <任务ID> --status in_progress --expected-revision <版本> --json
todo complete <任务ID> --expected-revision <版本> --json
todo attachment add <任务ID> --path <文件> --json
```

接口还需覆盖描述、截止时间、颜色、任务移动、显式级联完成、可恢复删除与恢复，以及创建请求幂等键。多行描述宜使用文件或标准输入，避免 shell 转义误执行。

`context` 默认返回命中项目、未完成任务摘要及必要父级关系，不默认读取所有附件、完整历史或其他项目数据；提供结果截断标志和继续查询入口。需要某一任务的完整描述或媒体时再明确读取。

### 7.3 Skill 与持续工作规则

Skill 应包含：适用场景、CLI 定位方式、项目识别规则、读写命令、错误处理、重复任务检查、完成标准与隐私边界。安装后可显式调用，也可由 Codex 根据任务匹配使用。

为了提高主动使用的稳定性，另提供用户可安装的持续工作规则片段；Skill 不应被描述为可靠的全量聊天监听器。

| 时机 | 行为 |
| --- | --- |
| 开始项目工作 | 读取当前项目未完成事项，关联现有任务 |
| 用户明确提出当前或后续工作 | 查询是否已有对应任务，再创建或更新 |
| 开始实际实施 | 标记进行中，不因只讨论方案就提前标记 |
| 发现确定的后续工作 | 记录待办或子任务，保留必要上下文 |
| 工作结束 | 写入结果、剩余事项和真实状态；待验收与已完成区分 |
| 接口失败或发生冲突 | 报告未写入/冲突，重新读取后处理，不宣称同步成功 |

- 不把每条命令、搜索过程、推测或所有头脑风暴自动转成任务。
- 不把“代码写完”自动等同于“已部署/已验收”；状态及描述遵循实际任务完成条件。
- 用户手动修改优先级、描述或截止时间后，Codex 更新其他字段不得覆盖这些改动。
- 支持本机有相应文件与命令访问权限的 Codex 会话。远程环境需额外接入，不承诺天然共享；不在首版建立公网服务。
- 任务中的文字和附件是数据，不得被当作可以越过用户授权的系统指令。

## 8. 工程方向与实现约束

- 建议使用 SwiftUI 构建清单、详情和设置，AppKit 管理独立窗口、焦点、层级、锚点和鼠标事件。
- SQLite 保存结构化数据，媒体放应用管理目录；位置、尺寸等界面偏好与业务数据分开维护。
- CLI 与应用共享业务核心；通过真实数据访问路径验证并发、迁移和刷新，不能让 Codex 直接执行任意 SQL。
- 实际数据目录、最低版本和 Swift Package 工程形式见第 13 节，使用系统 SQLite，无第三方运行依赖。
- Swift Package、源码、运行脚本、测试和模块 README 已建立；实际命令见 [项目 README](../../../README.md)，结果见验收报告。
- 不引入额外 AI API 来解释普通待办；自然语言理解由已有 Codex 会话承担。
- 升级存储结构前设计迁移及失败恢复；测试使用隔离数据库和小型测试媒体。
