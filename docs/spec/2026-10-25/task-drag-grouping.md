# 待办拖动排序与项目合并

- 日期：2026-10-25
- 状态：本地实现完成；自动化、原生浮窗及实际拖动排序/跨项目插入/合并触发通过，长列表与跨屏拖动仍未验证
- 来源：用户要求拖动卡片跟随鼠标、间隙插入亮线、未分类任务本体合并边框及选择浮窗；允许新项目先只填名称、以后绑定目录。
- 关联：[总体 Spec](../2026-10-24/macos-floating-todo.md)

## 目标与范围

在原清单中完成同级排序、跨项目插入、两条未分类任务合并到新项目或没有任何未删除任务的已有项目。不新增其他协作、提醒或云同步功能。不增加全局权限或第三方依赖。

## 交互规则

- 原生按住拖动，任务卡片预览随鼠标；悬停不写入数据，放手才提交。
- 行上/下边缘表示之前/之后插入，显示 2 pt 亮线。只有拖动项与目标项均未分类时，行中间区域显示新色边框，松手弹出合并选择浮窗。
- 有项目的任务本体不触发合并，按上/下半行表示插入。项目标题可接收拖动并追加到该项目的根层末尾，折叠项目也可接收；内容展开后可精确插入。未分类区域提供末尾落点，支持移出最后一条项目任务。
- 合并浮窗提供创建项目名称和现有空项目选择；默认创建新项目。取消/Escape/点外部不写入。确认时重新验证两条任务版本、未分类条件、目标空项目条件，原子完成；失败保留选择并提示。
- 父任务按完整分支移动。放在某层任务旁保持目标的父级；不靠拖动任务本体创建父子关系。禁止移动到自己/后代，不允许合并祖先与后代。
- 待办与已完成仍保持原有分区；插入只在相同完成分区内排序，不因拖动改变完成状态。不同项目始终按项目分组，未分类保持无框。
- 拖动后的同级顺序优先于自动优先级排序，并跨重启保留。未经过手动排序的组保留原排序；向已手动排序组新增任务排在末尾。
- 无目录项目用稳定 ID 识别，可在设置中绑定目录；未绑定目录不会匹配 CLI context。

## 数据与接口

- TodoItem 增加可选 sortOrder；旧快照缺省 nil，兼容读取。
- project create --name：创建无目录项目；保留 project bind 的原目录校验。
- place：带源版本、目标任务版本及 before/after，或显式 project/parent 的 end；复用 move 的分支/层级/循环校验，在同一事务设置顺序。
- group：带两条任务版本，name 或空 project 二选一，检查未分类且非同一分支；创建项目及两次分支移动在一个事务中提交。
- UI 与 CLI 走 Store.execute 同一校验；更新相关 Skill/CLI 帮助/模块文档。

## 2026-10-25 拖动无法启动反馈修复

用户实机反馈旧版按住不能拖动。移除外层 SwiftUI onDrag/NSItemProvider 析构清理入口，改为标题区原生 NSView 接收 mouseDown/mouseDragged/mouseUp：4 pt 阈值区分点击与拖动，用 beginDraggingSession 启动系统会话，系统 endedAt 回调负责取消/完成清理。禁止把任务拖到应用外，保留状态/展开按钮原操作。

编译和两项 DraggingTests 通过。独立标准 NSWindow 复用生产 ContentView，工具实际拖动已触发 prepare/starting/session returned/began 回调，日志 `.local/drag-source-data/preview.log`；说明系统会话确实启动。该工具的应用定向输入未完成系统松手/取消回调，因此仍未把整个落点交互判为通过；原非激活悬浮面板也仍需用户复测。没有以模拟模型落点替代真实拖动验收。

## 最终拖动路径修正（2026-10-25，替代前述系统拖放实现）

用户再次反馈仍不能移动。改为应用内局部鼠标追踪，不再将事件交给 NSDraggingSession：同一来源 NSView 处理按下/拖动/松手，NSPanel 只负责忽略输入的跟手卡片预览；窗口内实时注册的任务行/项目标题落点直接决定放手动作。命中范围取 bounds 与 visibleRect 的交集，避免 SwiftUI 宿主提供的大可见区域误选邻行。只在放手时提交原有事务；无全局输入捕获或重放。

- 使用原生产 ContentView 的独立普通窗口实际拖动，第一条移到第三条之后，CLI 断言顺序正确；两条未分类任务的中央拖放实际触发合并浮窗，取消成功。
- 随后使用原生产 FloatingController/TaskPanel（非激活、悬浮、accessory 模式）居中测试，实际拖动将 Beta 从首位移到末尾，CLI 确认 Alpha/Gamma/Beta；随后实际将 Alpha 插入 Drop Target 项目的 Target Task 后，UI 显示正确项目归属和顺序。没有直接调用模型伪造这些拖动结果。截图 `.local/drag-source-data/floating-cross-project.png`。
- 三项 DraggingTests 通过，增加任务行命中/区域外/隐藏行回归检查。编译通过，开发版已更新。此前“系统 began 但松手未完成”的证据只描述旧实现，不代表本版机制。
- 单帧工具未捕获完整跟手动画，长列表滚动、跨显示器、拖动中 Escape 的物理交互尚未逐项实测，保留边界；本次主要故障的真实位置移动已验证。

## 2026-10-25 项目整组拖动与顶层混合排序

用户授权：按住项目名拖动整个分组；任务可移到组外/组间，亮线必须位于真实组间落点，而不是已完成分区后。采用统一顶层顺序（项目分组 + 未分类未完成根任务），持久保存。项目拖动不改变任务归属或内部顺序；任务移到组间变为未分类根任务，带后代整支移动。未分类已完成任务仍在末尾独立折叠区，不参与未完成顶层排序。组内行/标题落点保留；组外插槽独立命中和高亮。项目颜色不因顺序变化重分配。

实施：可选 boardOrder/boardRevision 兼容旧快照；board place 原子校验版本、重排项目或移动分支到未分类并重排。UI 统一顶层块和插槽，复用原生局部鼠标追踪；组预览包含完整可见分组。验证核心顺序/并发/分支，及原生面板精确组间拖放。状态：已实现并通过编译、单元测试与原生实拖验证。
