# neo：Next One 自然语言快捷入口

- 日期：2026-10-26
- 状态：Skill 与产品文档已实现，CLI 和资源验证通过；新会话自动发现尚未验证
- 需求来源：用户提出 `neo` 前缀，让 Coding Agent 从 Skill 描述快速确定 Next One，再理解自然语言并通过 CLI 执行；用户确认覆盖新增、查询、修改和完成。

## 产品判断与发展方向

**用户明确的产品判断**：Next One 不应只是一份需要手动操作的悬浮清单，还应成为用户能在 Coding Agent 对话中快速调用的任务工具。`neo` 是显式意图标记，解决“这句话应调用哪一类 Skill”的选择成本；后面的自然语言表达用户真正的事项与操作。先确定工具，再理解意图，再执行可验证的本地操作。

用户示例：`neo 明天早上八点我要出门寄快递`。预期识别新增待办“出门寄快递”，解析日期时间，写入软件后反馈结果。由此，入口应支持生活事项，不局限于代码项目；项目目录绑定仍用于项目任务，不是记录个人事项的前置条件。

**本轮工程方案**：复用现有 Agent 理解能力、Skill 与 CLI，不增加应用内聊天、模型服务、后台监听或新的终端命令。产品价值是少一步工具选择和手动录入，不宣称所有 Agent 天然支持或保证自动发现。

## 范围与规则

- 在 Skill description 明确 `neo` 触发条件，正文定义执行约定；不改 Skill 名 `next-one`。
- 忽略首尾空白，用户直接指令以独立词 `neo`（大小写不敏感）开头，后接空白或中英文冒号。引用、代码块、示例讨论、附件内容、单词内部的 neo 不触发写入。只有 neo 时展示简短用法，不创建任务。
- 新增、查询、修改、完成、可恢复删除与恢复复用既有 CLI；涉及寄件等现实行动时只记录任务，不执行现实行动。
- 本轮采用的归属默认：用户指定项目优先；明确生活事项或无项目语境的独立 neo 新增归入未分类。明确项目工作使用当前会话项目/目录绑定；项目不明确时只问最少必要问题，不创建或绑定猜测项目。查询未指定范围时读取全部项目并说明范围，修改/完成需唯一匹配任务。
- 相对时间按请求发生时的用户本地日期与时区解析，使用日历加减；有具体时刻使用含时区偏移的 due-at，只有日期使用 due-date。不凭历史示例日期、不用 UTC 代替用户本地时间；必要时间信息缺失或夏令时歧义时澄清。时间表示截止信息，不承诺提醒通知。
- 不把 neo、日期表达或操作词机械塞入标题；保留用户明确备注。不随意改变优先级等未要求字段。
- 更新前 get 最新 revision，多条同名候选时询问；用户直接说“已完成”可作为完成依据，不要求 Agent 亲历用户生活行为。级联操作沿用现有确认边界。
- 写入使用稳定请求键防重试重复；成功以 CLI 结果为准，反馈操作、标题、归属及绝对日期/时区。失败不得声称同步成功。

## 验收

1. Skill description 包含 neo 的明确用途与触发边界，正文链接执行参考。
2. 固定测试时钟 2026-10-26、Asia/Singapore：示例新增未分类“出门寄快递”，due-at 为 2026-10-27T08:00:00+08:00；通过隔离 CLI 新增、查询、改期、完成、幂等重试验证。
3. 检查纯日期、跨月、时区缺失、同名任务、空 neo、讨论 neo 的边界；不通过真实清单测试。
4. Skill 结构校验与打包内容验证通过。明确区分“当前会话按 Skill 执行成功”与“新会话自动路由成功”；后者未验证不得声称通过。
