# 长编号提示与完成归档

- 日期：2026-10-26
- 状态：已实现；自动测试及隔离原生流程通过
- 来源：用户要求存在 4 位编号时固定提示、归档完成任务、从头跳过占用编号、恢复重新编号。

## 范围与规则
- 编码规则不变，3 位以内容量为 6,318，非硬性长度限制。所有未删除任务中有 shortCode.count >= 4 时，在清单顶部（工具栏下、滚动区外）持续显示“编号开始变多？”及“归档已完成Todo”。切换项目仍检测全局；无完成任务时也可确认归档0项并重置分配游标，不改变存量编号。
- 点击后确认全局影响：所有项目、含未完成父任务下已完成子任务；可取消。确认以候选完成任务 ID/revision 摘要防并发误归档；变化时拒绝并刷新重试。
- 原子归档所有未删除 done 任务，不更改未完成任务。每个连续完成分支使用独立 deletionID，保留原父子关系及附件。恢复继续遵守先恢复父级的原有规则。
- 归档成功将 nextTaskNumber 置 1；新建从 A1 顺序寻找未占用编号。仍存在长编号的未完成任务时提示继续显示，不重排存量任务。
- 唯一性以当前未删除任务为准。普通删除和归档均清空回收站任务的 shortCode，使其不占号；回收站使用 UUID 操作，绝不凭旧编号恢复，以免误指向复用编号的新任务。
- 任意恢复操作为恢复分支各任务按创建时间/UUID顺序重新分配编号，跳过当前占用。编号不保证与归档前不同，但不承诺旧编号仍指向同一任务；Skill 必须先 get 核对标题/UUID，执行使用 UUID。
- 编号可复用后，短编号用于 get 查询；所有任务写入使用查询返回的 UUID（包含 parent/anchor/target）。拒绝以可复用短编号直接写入，防止旧编号与相同 revision 误命中新任务。UI 已使用 UUID，Skill 同步先解析再操作。
- 存储 v3 兼容 v1/v2 迁移；已有未删除编号不变、回收站编号清空；不重置原分配游标，只有主动归档重置。升级需退出旧程序，禁止旧版写入新库。

## 接口与实现
- `archive preview` 返回全局 count/token；`archive completed --expected-token TOKEN [--request-key KEY]` 原子归档和重置，返回 affected_ids/count。复用 SQLite 事务和请求幂等，不新加依赖。
- SwiftUI 顶部固定通知；AppModel 使用共享 Snapshot 候选摘要，确认后调用同一 Store 命令。四语文案与仓库 Skill/CLI 契约同步。
- 编号分配复用集合检查，批量恢复只构建一次占用集合；归档一次扫描并按祖先确定删除分组，不对每条任务反复遍历全库。
