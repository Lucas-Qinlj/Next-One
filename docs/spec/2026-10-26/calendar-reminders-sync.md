# 同步到日历与手机完成状态回传

- 日期：2026-10-26（Asia/Singapore）
- Feature ID：`calendar-reminders-sync`
- 状态：2026-10-26 本地实现完成，主要 Mac/iPhone 链路与自动测试通过；系统边界未全部验收，见验收记录。
- 需求来源：本轮用户需求、截图及八条批注；用户确认采用截图中的“提醒事项”，接受其同时出现在系统提醒事项 App；用户已开启手机 iCloud 提醒事项同步，愿意配合实机验证，操作前须提前告知。
- 关联：[总体产品 Spec](../2026-10-24/macos-floating-todo.md)、[编号规则](task-short-codes.md)、[归档规则](archive-completed.md)、[核心模块](../../../Sources/TodoCore/README.md)。本 Spec 是新增同步能力的事实来源，补充总体 Spec 首版不含同步的历史边界。

## 1. 目标与授权边界

通过 Apple EventKit 创建、维护系统提醒事项，由 iCloud 同步至同一 Apple 账户的 iPhone；有日期的提醒事项可在系统日历展示。支持 Next One 修改、完成、删除向外同步，以及手机勾选／取消勾选完成状态回传。无需额外安装手机 App、部署服务器或接入第三方推送服务。

用户已明确授权当前会话实施；不启动 KF、新会话、子代理或 GOAL。系统测试使用隔离数据和专用测试条目，手机验证前提前通知。本文件标注的建议默认值可以作为工程默认，不要求用户逐项重新确认。安装现用应用、推送和发布不在本轮授权中。

## 3. 平台事实、限制与未验证事项

- API 使用 `EKReminder`，不是 `EKEvent`。通知来自系统提醒事项；日历只是展示／编辑入口，无需再创建日程。开启 iCloud 的项目为“提醒事项”。
- 项目最低 macOS 14 支持 EventKit 接入；在日历显示提醒事项需 macOS 15／iOS 18 或更新系统，且系统日历启用提醒事项显示。旧系统可在提醒事项 App 中使用，不伪称日历显示已支持。
- 通过 `requestFullAccessToReminders` 申请提醒事项读写权限，打包补充对应隐私用途说明。只为本功能申请必要权限，不因日历展示申请无关日历事件访问、辅助功能或屏幕录制权限。
- EventKit 公开接口无图片／视频附件写入和父子关系写入能力。不得用私有 API、直接改系统数据库、界面自动点击或本地文件 URL 绕过。
- **自动开启 Urgent 紧急闹钟：未满足，当前不实现。** 已核对公开 `EKReminder`／`EKCalendarItem` 文档与本机 SDK，无该开关；高优先级、`EKAlarm` 普通提醒不是 Urgent。AlarmKit 也不是设置系统提醒事项 Urgent 的接口。若未来官方 API 新增能力，应独立重新评估，不在实施中静默换成私有方案。
- 用户可在系统提醒事项中手动开启 Urgent，但这不是自动功能验收。Apple 说明其受闹钟权限和“查找”位置设备选择影响。更新普通字段时必须实测不清除用户手动设置的 Urgent 等未管理属性；若无法保留则暂停该条更新并记录限制。
- iCloud 负责跨设备传输；EventKit 写入成功仅证明 Mac 本地系统已接收，不提供“iPhone 已收到”的送达证明。专注模式、通知权限等影响展示；不承诺秒级同步、必定响铃或绕过静音。
- 初始调研仅覆盖源码、SDK 和官方资料；实施后构建、系统写入及用户配合手机验证的实际结果见第 15 节及验收记录。

## 4. 建议默认值

以下是为实施完整性明确的建议，不表述为用户逐项指定；实施可直接采用并记录。

1. 默认关闭，用户主动开启并选定清单后才同步。同步范围为所有项目中有截止日期／具体时间的任务，不额外增加项目选择配置。
2. 首次启用仅新建未删除、未完成且有日期的任务；不批量导出历史已完成项。已有映射对象后续完成仍保留映射并同步完成，直至删除／归档或移除日期。
3. 标题中的方括号仅为占位符，实际拼接为 `A1-提交方案`（用户已明确纠正）；不额外给原标题加状态／项目标签。标题中的原有符号不修改。映射绝不解析标题来确定身份。
4. 具体时间按到点提醒，首版无提前提醒配置；仅日期映射全天项，不擅自增加具体响铃时间，系统自己的全天提醒设置仍可能产生通知。无日期任务不创建映射。
5. 单条外部记录仅完成状态自动回传；取消完成恢复到其完成前的 `todo` 或 `in_progress`，无可靠历史时为 `todo`。
6. 关闭同步默认为暂停并保留已有系统提醒事项和映射，不隐式批量删除；确认关闭时解释“已有提醒仍可能通知”，无需每次设置微调确认。
7. 切换目标清单采用迁移既有受管对象的方式，需确认影响数量；不保留两份有效提醒，不移动该清单里用户自己创建的条目。

## 5. 设置交互

同一紧凑行放置“同步到日历”、问号、清单选择器和开关；窄宽度下可以自然换行，不裁剪清单名称或预留大块顶部空白。遵守待办详情的中性样式、间距、字号及四语本地化。

### 5.1 开启与选择清单

- 2026-10-27 用户补充：设置页显示期间立即读取并每 2 秒刷新目标清单，离开设置页自动取消；后台刷新不重新申请权限、不改当前目标 ID、不自动开启同步。新增／删除／改名通过最新清单反映，无变化不重复替换列表，避免干扰选择。遇授权或同步正在执行时跳过本次读取，下次继续。

1. 默认不触发系统权限弹窗。用户主动开启后申请提醒事项权限；拒绝时不进入已启用状态，可提供系统设置入口。
2. 枚举可写的提醒事项清单，按账户／来源分组，显示“账户 · 清单名”；仅列候选元数据，不导入无关清单内容。
3. 由用户选择 iCloud 下目标清单。不能仅凭 `sourceType == calDAV` 或清单名判定 iCloud；没有可靠来源识别时明确显示实际账户名称，让用户选择，不冒称已验证云端能力。
4. 无清单时提示用户在系统提醒事项中创建；不默认自动创建、改用本机清单或其他账户。共享清单如可识别需标明共享，提醒其内容对共享成员可见；不能声称 API 一定能可靠识别所有共享状态。
5. 首次启用显示将同步的数量和内容范围（标题／描述／时间等，不含附件），确认使用所选清单；不把开关操作授权扩大到导出本机目录、代码或任意已有提醒。
6. 保存清单 ID 和来源 ID，不按名称自动重绑。清单失效／权限撤销只给必要、去重、可恢复反馈，保留本地任务。

### 5.2 问号文案基准

> 开启后，有截止日期的待办会同步到所选提醒事项清单，并可在系统日历中显示。请在 Mac 和 iPhone 登录同一 Apple 账户，选择 iCloud 清单，并开启 iCloud「提醒事项」同步和通知权限。日历展示需 macOS 15／iOS 18 或更新版本。
>
> Next One 中的修改、完成和删除会更新对应提醒事项，手机勾选或取消完成也会回传。图片、视频及其他附件不同步，子任务以独立条目显示。紧急优先级不会自动开启系统的紧急闹钟；关闭同步会保留已有提醒事项。

问号支持悬停、点击与键盘访问，提供无障碍名称；说明不要求用户理解 EventKit、UUID 或内部存储。普通断网／休眠无 toast、计数或常驻同步状态；权限、无效目标和需要决定的冲突可以显示必要反馈。非阻断反馈遵守 3 秒底部覆盖浮层规范，确认对话框不自动消失。

## 6. 字段映射与生命周期

| Next One | EKReminder / 系统含义 | 规则 |
| --- | --- | --- |
| UUID | 本地映射键／来源标记 | 不使用可复用短编号作为身份 |
| shortCode + title | title | `A1-标题`，恢复重新分配编号后更新 |
| description | notes | 纯文本原样保留；独立来源区记录来源标记、项目名、父级标题路径 |
| projectID / parentID | 来源区上下文 | 不上传绑定目录；层级展平；项目改名、移动、父级改名也重新计算受影响后代投影 |
| dueAt | dueDateComponents + 普通 EKAlarm | 保留绝对时间语义；未来时间安排到点提醒；与 startDateComponents 的要求按 SDK 验证 |
| dueDate | 日期组成部分 | 不经 UTC 转换造成日期偏移；不添加 Next One 指定的响铃时间 |
| priority | priority | high→1、medium→5、low→9，不设置 Urgent |
| todo / in_progress | isCompleted = false | 本地保留三态，不把 in_progress 降成 todo |
| done / completedAt | isCompleted / completionDate | 保留有效完成时间，移除本应用管理的未来提醒 |
| 附件、颜色、排序 | 不映射 | 不上传图片／视频／本地路径；不改用户在系统侧附加的未管理数据 |

- 无日期→有日期：符合资格后创建；有日期→无日期：移除对应受管提醒，保留删除重试记录。仅日期与具体时间切换时同步清理失效的受管 alarm。
- 首次同步已过期但未完成的任务可显示为过期项，不补发历史到期通知；必须实测系统是否自行产生补发通知，不将应用未建 alarm 等同绝对不会通知。
- 完成／重新打开均更新原对象；重开仅为未来具体时间重新建立受管普通提醒。
- 删除、归档操作覆盖所有实际受影响 UUID；删除成功前不得清空映射。绝不删除整个清单。恢复用原 UUID 关联，但若系统旧对象已不存在，则创建新对象并替换其 Apple ID。
- 不支持从手机删除反向删除本地任务，亦不导入手机新建条目。

## 7. 完成状态双向同步与冲突

### 7.1 自动回传

- 通过系统变更通知触发重新读取，启动／恢复运行时补对账；通知只是重新读取信号，不当作单条变更事实。
- 对受管记录比较上次双方同步基线。远端完成且本地未改该状态：通过共用业务入口完成本地任务；远端取消完成同理恢复本地状态。
- 本地仅修改标题而远端修改完成状态，可以按字段合并，不因整个 revision 改变直接判所有字段冲突；写回仍用最新 revision，失败重新读取，不覆盖更新较新的字段。
- 写回更新基线，禁止同一次完成在两端形成循环、反复写入和重复提示。启动首次对账不得先把旧本地状态推回远端，抹掉手机刚完成的结果。

### 7.2 父子与同时修改

- 远端完成叶子／无未完成后代的父任务：直接回传。
- 远端完成存在未完成后代的父任务：该条进入待确认，不自动级联、不自动反转手机操作。Next One 提示影响数量，提供“同时完成子任务”或“保持未完成”；后者恢复父任务系统状态。确认前不推进该分支冲突对象，其他任务继续同步。
- 取消完成子任务按现有 Store 规则重新打开必要祖先，并同步那些有映射的祖先。
- 双方相对基线对同一字段作出不同修改时不按设备时间戳粗暴覆盖。冲突仅针对该对象，提供“使用 Next One 内容”或“保留系统侧内容并停止该条同步”；完成状态冲突可在双方状态间明确选择，再通过共用业务规则处理。
- 手机修改非完成字段、将受管对象移到其他清单或删除对象：不反向改／删 Todo，也不自动覆盖／重建；确认真实缺失前排除权限、来源加载失败和 ID 变化。确认外部变化后提示一次并暂停该条，允许明确恢复同步或停止该条同步。停止记录持久化，重启不能立即再次创建。
- 未管理属性（用户手动图片、重复、标签、Urgent 等）不主动清除。若系统侧改动导致一个 Todo 对应重复发生的提醒等语义不兼容，暂停该条处理；不能声称所有不可见属性均可可靠检测，兼容性靠实际验证并记录限制。

## 8. 持久化映射与失败恢复

### 8.1 最小记录

本地数据集稳定标识 + Todo UUID 唯一确定受管对象。保存目标来源／清单 ID、Apple 本地对象 ID、可用时的外部 ID、来源标记版本、上次双方受管字段基线、完成前状态、同步配置代次，以及待执行／暂停／待确认操作。内部错误信息脱敏，不持久化无关提醒事项全文。

来源标记建议在 notes 独立来源区使用版本化的 `NextOne:v1:<dataset-id>:<todo-uuid>`；它是可见来源信息，不是秘密。需验证 iCloud 往返及用户编辑后的保留行为，不以标题匹配兜底。多个标记命中、标记被复制或身份不确定时暂停，不猜测或删除。

### 8.2 顺序与幂等

1. 本地任务修改和可重建的同步意图／版本记录可靠保存；同步失败不撤销用户本地保存，不阻塞 SQLite 事务等待系统 API。
2. 由主应用中一个串行协调器执行 EventKit 读写，短时间连续编辑合并为最新投影。不同进程不能同时创建同一条对象；使用必要的进程互斥保护。
3. 创建前按映射 ID 查找；失效时在已知受管范围按来源标记找回。外部 ID 只作辅助，不假设全局永久唯一。
4. 写入成功后记录实际对象 ID及本次已提交版本。期间本地再次编辑时不能把旧响应当成最新完成；继续同步新版本。
5. 系统创建成功、本地映射尚未保存就中断：下次按事先持久化的来源标记收养原对象，不重复创建。
6. 删除意图持久化，远端删除及映射收尾可重试；仅在有权限且目标已完整读取时把“确实不存在”视为删除完成。
7. 离线、进程退出、休眠后通过启动／唤醒／周期性有限重试补偿；不依赖某一次通知或联网事件，重试退避不刷屏，不轮询整库每 0.7 秒写 EventKit。
8. 暂停开关、目标切换和配置代次在执行前重新核对；关闭时停止调度，已发出的请求完成后仍记账，不遗留无映射副本。切换清单优先在原对象上迁移；无法保留身份则按可恢复步骤迁移并防重复，不假设跨账户移动受支持。

Apple 与本地数据库不能组成一个原子事务，因此上述补偿规则是验收内容。保留本地任务数据为主，手机仅对完成状态产生明确受控的输入。

## 9. 模块与接口边界

这是一个独立同步功能，不拆成额外服务。复用 SwiftUI／AppKit、TodoCore、SQLite 和系统 EventKit，不引入通用同步框架。

| 位置 | 责任与改动方向 |
| --- | --- |
| `Sources/TodoCore/Models.swift`、`Store.swift` | 保存映射／基线／待处理记录，投影规则，共用状态校验、revision 与事务；具体文件拆分以最简方案为准 |
| `Sources/TodoApp/` | EventKit 适配与串行协调、应用生命周期、设置控件、权限／冲突交互 |
| `Sources/TodoCLI/`、`Skills/next-one/` | 既有修改入口产生同等同步结果；说明应用未运行时先本地保存、运行后补同步，不声称 CLI 返回等于云端送达 |
| `Sources/TodoCore/Resources/` | 四语设置、说明、权限／冲突反馈 |
| `scripts/package-app.sh` | 应用权限用途说明及包内资源；核对实际签名／沙盒配置，不凭文档假设权限已生效 |
| `Tests/TodoCoreTests/`、`Tests/TodoAppTests/` | 字段投影、映射、协调与失败恢复针对性测试 |

UI／CLI／手机回传均复用 Store 的业务验证；不得直接写任务快照绕过父子状态、版本冲突或删除规则。新增内部接口与错误码需在实施时同步模块 README 和调用方；不为此增加通用网络端口。

当前模型为存储 v3，主应用轮询本地 Snapshot，尚无 EventKit 集成。新增持久化结构必须兼容现存数据并明确 schema 版本策略；未知新 schema 的旧 CLI 不得静默覆盖同步元数据。测试／debug 数据集和正式数据分别配置目标，禁止测试环境沿用正式映射。恢复备份或复制数据集后先对账身份，不自动制造第二个写入者。

保留现有 Swift 风格，例如通过 `store.execute("complete", ["id": uuid, "expected-revision": String(revision)])` 进入既有规则；不能默认附带 `cascade: true`。EventKit 网络／系统等待不占用 Store 写事务。
