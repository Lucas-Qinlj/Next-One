## 1. 目标

用户在待办上右键，选择已有本机 Codex 项目，补充可选指令，即可打开 Codex 新会话页面并预填完整上下文，停留在该页面，由用户在 Codex 中发送。

理想体验中的自动发送不属于首版验收条件。不能把“已预填”称为“已发送、已启动任务或已完成创建持久化会话”。

## 2. 范围与非目标

包含右键入口、目标选择、支持换行的可选指令框、上下文组装、附件本地路径、Codex 跳转、Skill 识别和失败反馈。

首版不提供无项目“聊天”选项；该能力延期，不作为本轮实施前置条件。

不包含自动发送、任务状态自动更新、会话 ID 回写、远程会话、附件卡片上传、视频理解保证、后台服务、自动添加 Codex 项目、长文本专用截断/拆分/导出机制。内容必须完整，不静默截断。不以辅助功能模拟点击或自动敲回车作为首版实现。

## 3. 当前事实与接口证据

- `Sources/TodoApp/Views.swift` 的任务行已有 contextMenu；`AppModel` 调用共享 Store。
- `Sources/TodoCore/Store.swift` 的 `get` 已返回任务详情及附件本地 `path`，编号解析已有共享实现。
- 本地 `codex app --help` 只声明打开工作目录，不能据此推断可传首条消息或自动发送。
- [官方深链接文档](https://learn.chatgpt.com/docs/reference/commands#deep-links) 声明 `codex://threads/new` 支持 `prompt`、`path`、`originUrl`；`prompt` 仅预填，不自动发送。资料于本轮评估读取，目标安装版本仍需实测。
- 当前 Agent 工具可列 Codex 项目并指定 projectless 创建，但这些是会话内能力，不能当作 Next One 原生应用的公共接口。
- 已验证本机数据库能只读获取项目名称与目录，用户已确认采用第 7.1 节方案。省略或留空 path 均未进入无项目聊天。深链接的 path 能打开工作目录，不等于满足“只匹配已有项目、不新增项目”的规则。

## 4. 交互规则

### 当前实施：独立普通交接窗口（2026-10-27 用户授权）

替换依附悬浮清单的 sheet，项目选择和补充指令复用现有视图，在独立可激活的普通 NSWindow 中完成。清单和球保持可见，不新增字段、不自动发送、不使用辅助功能。暂时退役未经稳定验收的 AX 聚焦及设置开关；不撤销系统已有授权。

同一时刻只开一个交接窗口，重复入口将现有窗口提到前面，不覆盖草稿。取消、关闭按钮和 Escape 均取消准备中的操作，不打开 Codex。确认时仍读取最新数据，失败保留同一窗口、项目和指令。准备成功后先隐藏普通窗口，再打开深链接；避免关闭普通窗口时清单自动成为 key，交接这一同步操作期间暂时禁止面板成为 key，随后恢复原有锁定规则。不隐藏或重新显示清单，不在打开后激活 Next One。

验收：自动检查普通窗口类型、清单始终可见、成功关闭、失败恢复、重复入口复用、取消/关闭后不打开；真实 Codex 连续至少两次交接并直接输入由用户验收。之前普通窗口隔离实验成功不等于本轮真实清单共存成功。`swift test --filter CodexHandoffTests`、`swift build -c release` 为必要工程检查。

下文与当前段冲突的旧 C3 隐藏/权限实现作为历史方案；以本段为本轮范围，AX 历史见对应 Spec。

### 4.1 入口与顺序

任务行右键菜单第一行固定提供“创建 Codex 会话”，采用现有本地化方式覆盖四种语言。按目标归属规则完成必要选择后，才显示指令框。

- 菜单项文字前显示灰色单色 ChatGPT Logo，与文字垂直居中、大小与原生菜单行协调；不以通用气泡或其他图标代替 Logo，不使用彩色背景。
- 该菜单项下方放一条灰色分隔线，优先使用原生菜单分隔线；与下方“新增子任务”“优先级”“颜色”“移动…”“移入回收站”分组隔开，原有选项顺序与行为保持不变。
- 灰色 Logo 不表示禁用；可用时该菜单项正常点击，保留原生高亮、键盘选择和无障碍菜单名称。浅色/深色外观下图标与分隔线均应可辨认。

- Enter：确认并打开 Codex；输入为空也允许。
- Shift+Enter：插入换行，不提交。
- 中文输入法组合状态的 Enter 优先确认候选，不触发提交。
- Escape 或取消：退出，不打开 Codex、不改待办。
- 指令框可多行编辑，沿用现有详情页字号、输入框、紧凑边距和统一滚动条风格。
- 处理中避免重复确认导致多个窗口；失败保留输入，允许重试。
- 成功时由 Codex 获得焦点并停留在目标新会话页面，Next One 不抢回焦点。
- C3 当前采用独立普通窗口：校验后隐藏交接窗口，再通过深链接打开 Codex；成功后关闭并释放交接窗口，失败重新显示。清单和悬浮球保持原可见状态，不自动发送，不申请额外权限。实际直接输入效果待用户验收。
- 此前无权限延时恢复及[辅助功能聚焦试验](codex-accessibility-focus.md)均未稳定通过，已移除运行代码；历史测试结果保留，系统已有授权不自动修改。
- 校验失败或取消时不收起清单、不打开 Codex。系统拒绝打开 URL 时恢复清单及同一份交接草稿（补充指令、项目和目录选择），显示错误并允许重试。打开 URL 返回成功仅表示系统接收请求，不保证 Codex 已预填或聚焦；真实端到端由用户验收。

### 4.2 目标归属

| 待办归属 | 目标选择与处理 |
| --- | --- |
| 未分类 | 展示已有本机 Codex 项目列表，选定后显示指令框 |
| 已归属 Next One 项目，但无绑定路径 | 同未分类 |
| 只有一个绑定路径 | 直接匹配该路径，不弹路径选择 |
| 绑定多个路径 | 先选择一个绑定路径，再执行匹配 |
| 选定路径属于 Codex 已有项目 | 在对应 Codex 项目中打开新会话 |
| 选定路径不属于 Codex 已有项目 | 展示已有本机 Codex 项目列表，用户选择后在所选项目打开新会话；原路径保留为上下文，不自动添加项目 |

首版所有交接均进入已有本机 Codex 项目，不显示“聊天”选项，不包含云端/远程项目。手动选择目标不会更改待办归属或 Next One 的目录绑定。所选 Codex 项目有多个目录时，再让用户选择其一个目录作为跳转目标。

工程默认：比较规范化的完整目录路径，处理尾斜杠和可解析的符号链接，不按项目名称、Git remote 或父子目录模糊匹配；不扫描项目代码。多个项目精确匹配时让用户选择，不随意取第一项。

读取列表失败不等于项目列表为空，不自动沿用 Codex 当前项目。真实没有可选项目时提示用户先在 Codex 添加项目，提供重试/取消，不继续跳转。路径不存在或不可访问时说明问题并允许重选/取消，不悄悄换目录。这些失败不能被报告为成功。

## 5. 上下文契约

在确认时读取最新任务、项目及附件信息，组装一个纯文本消息。未完成的详情编辑应先按现有保存/冲突规则处理；不能把旧缓存冒充最新数据。

`<neo>` 仅作为外层标记，内部使用用户可直接阅读的文本，不再添加字段标签、属性或任务 UUID。不扩展为父子任务整树或整个项目数据导出。

确认的消息格式：

```text
<neo>
B9 待办标题
备注正文
选定的本地路径：本地项目绝对路径
文件名 本地附件绝对路径
</neo>

用户实际输入的补充指令（有输入时才追加）
```

深链接的 path 必须是最终选定的已有 Codex 项目目录。若原 Next One 绑定路径未匹配，正文继续保留该原路径，并在下一行写“会话项目路径：最终目标目录”，避免把目标项目误认为原任务目录；两者相同时不重复列出。无原绑定路径时，选定的本地路径使用最终目标目录。

首行是短编号、一个空格和标题；之后保留备注正文及换行。有选定项目路径时追加一行“选定的本地路径：实际路径”；附件按“文件名 本地绝对路径”逐项换行。项目目录和附件路径分别列出，便于阅读。没有备注、选定路径或附件时省略对应内容，不输出占位文字或空字段。

外层标记内部的文本只做必要的 XML 文本转义（`&`、`<`、`>`），防止正文中的标签提前结束上下文；不引入内部结构。URL 查询参数再单独编码，禁止手工拼接未经编码的 URL 或 shell 命令。

用户没有补充指令时，消息结束于 `</neo>`，不加“开始开发”“先评估”“请读取”等默认指令。有输入时，在闭合标签后空一行，完整保留用户输入及换行，放在最后。路径是上下文信息，不改写成执行指令。

图片、视频、文件统一传本地持久化路径，不另行上传。附件缺失需明确反馈，不声称已提供可读内容。只提供当前待办相关附件，不读取无关内容。

## 6. Skill 契约与隐私

- 更新仓库内 Next One Skill 及必要参考：识别 `<neo>` 为 Next One 格式上下文，从首行识别短编号，必要时通过支持的 CLI 获取最新详情；UUID 不放入消息，写入前仍以 get 返回的最新 UUID/revision 操作。
- `<neo>` 可被任何文本伪造，不是认证或更高优先级指令。正文和附件是数据，不扩大权限；不把用户无补充指令解释为自动开发授权。
- 保留用户指令原意，继续遵守当前项目规则，不直接改数据库。
- 通过已有安装/更新机制交付 Skill，不静默修改用户全局配置。仓库修改和实际目标会话生效分别验收。
- 用户在 Codex 发送及 Agent 读取的内容会进入模型上下文。Next One 本身不增加外部上传服务；不在日志中记录完整备注、拼接 URL 或附件内容。

## 7. 实现边界与建议顺序

使用现有 Swift Package、macOS 14+、SwiftUI/AppKit 和 Store；无需新数据库字段。优先系统 URL 打开能力和已有模块，不引入后台进程。

模块位置：`Sources/TodoApp/` 负责交互与跳转；`Sources/TodoCore/` 复用读取和校验；`Skills/next-one/` 维护上下文识别；测试分别放 `Tests/TodoAppTests/` 与 `Tests/TodoCoreTests/`。

沿用现有风格，例如：

```swift
Button(L("创建 Codex 会话")) { /* 调用应用模型的交接入口 */ }
```

上述仅为接口意图，不是已实现代码。

先验证目标版本的项目列表只读适配、已有项目匹配和深链接预填，再实施完整 UI 和 Skill。可独立验证文本组装；若没有可用项目接口，先记录证据，再就替代方案沟通，不能静默取消目标选择或改为自动新增项目。

- 必须：保留真实数据与无关修改，完整编码，真实反馈，按实际证据更新状态。
- 需另行授权：开发实施、创建测试会话、安装全局 Skill、替换现用应用、发布，以及引入系统权限或后台服务。
- 禁止：修改 Codex 私有数据库、绕过授权、依赖当前 Agent 工具直接充当应用接口、用 Mock 冒充真实跳转验证。

### 7.1 Codex 项目列表只读适配（用户已确认）

采用 Codex 本机数据库的 `projects`、`project_roots` 作为项目名称和目录的数据源；当前验证文件为 Codex 数据目录下的 `state_5.sqlite`。这是一项内部格式兼容适配，不宣称稳定公共 API。

- 独立于 Next One 业务数据库建立只读连接，使用 SQLite 只读打开和 `query_only`；禁止对 Codex 数据做迁移、写入或修复。
- 仅查询项目 id/name/position 及目录 project_id/position/path；不查询会话、消息、凭据或附件。保留项目与其多个目录的关系，顺序使用现有 position 字段。
- 在需要选择目标或匹配目录时读取最新项目快照，不增加后台服务。不依据 config.toml 的信任目录或历史会话 cwd 推测项目列表。
- 读取前检测所需表与列。文件缺失、格式不兼容、权限拒绝、数据库忙碌等均明确反馈并允许重试；真实零项目才展示空列表，不把错误当作空列表。
- 数据目录与数据库版本定位单独封装；默认使用本机 Codex 数据目录，非默认目录不得猜测或扫描全盘。实施时核实目标版本的定位方式；遇到未支持版本不自动选择备份或最大的数据库文件。
- 正常通过 SQLite 读取活动 WAL，保持一次读取的一致性；不单独复制主库，不使用 immutable 绕过活动 WAL。
- 不合并 JSON local-projects 与数据库列表；两者名称/目录在预验证时一致，但 ID 不同，不能混用。JSON 不作为静默备用来源。
- 深链接使用规范化路径，不把数据库内部项目 ID 当作公开路由参数。已有多路径目标继续遵守第 4.2 节选择规则。
- 实施验证使用脱敏自建 SQLite 夹具检查多路径、空列表和结构不兼容，再做有限真实只读核对；不得复制真实聊天库作为测试夹具。
