## 1. 目标

用户在待办上右键，选择目标项目或聊天，补充可选指令，即可打开 Codex 新会话页面并预填完整上下文，停留在该页面，由用户在 Codex 中发送。

理想体验中的自动发送不属于首版验收条件。不能把“已预填”称为“已发送、已启动任务或已完成创建持久化会话”。

## 2. 范围与非目标

包含右键入口、目标选择、支持换行的可选指令框、上下文组装、附件本地路径、Codex 跳转、Skill 识别和失败反馈。

不包含自动发送、任务状态自动更新、会话 ID 回写、远程会话、附件卡片上传、视频理解保证、后台服务、自动添加 Codex 项目、长文本专用截断/拆分/导出机制。内容必须完整，不静默截断。不以辅助功能模拟点击或自动敲回车作为首版实现。

## 3. 当前事实与接口证据

- `Sources/TodoApp/Views.swift` 的任务行已有 contextMenu；`AppModel` 调用共享 Store。
- `Sources/TodoCore/Store.swift` 的 `get` 已返回任务详情及附件本地 `path`，编号解析已有共享实现。
- 本地 `codex app --help` 只声明打开工作目录，不能据此推断可传首条消息或自动发送。
- [官方深链接文档](https://learn.chatgpt.com/docs/reference/commands#deep-links) 声明 `codex://threads/new` 支持 `prompt`、`path`、`originUrl`；`prompt` 仅预填，不自动发送。资料于本轮评估读取，目标安装版本仍需实测。
- 当前 Agent 工具可列 Codex 项目并指定 projectless 创建，但这些是会话内能力，不能当作 Next One 原生应用的公共接口。
- 尚未验证外部应用如何读取 Codex 项目列表，以及不传 path 时是否真正打开无项目聊天。深链接的 path 能打开工作目录，不等于满足“只匹配已有项目、不新增项目”的规则。

## 4. 交互规则

### 4.1 入口与顺序

任务行右键提供“创建 Codex”，采用现有本地化方式覆盖四种语言。按目标归属规则完成必要选择后，才显示指令框。

- Enter：确认并打开 Codex；输入为空也允许。
- Shift+Enter：插入换行，不提交。
- 中文输入法组合状态的 Enter 优先确认候选，不触发提交。
- Escape 或取消：退出，不打开 Codex、不改待办。
- 指令框可多行编辑，沿用现有详情页字号、输入框、紧凑边距和统一滚动条风格。
- 处理中避免重复确认导致多个窗口；失败保留输入，允许重试。
- 成功时由 Codex 获得焦点并停留在目标新会话页面，Next One 不抢回焦点。

### 4.2 目标归属

| 待办归属 | 目标选择与处理 |
| --- | --- |
| 未分类 | 展示本机 Codex 项目列表及“聊天”，选定后显示指令框 |
| 已归属 Next One 项目，但无绑定路径 | 同未分类 |
| 只有一个绑定路径 | 直接匹配该路径，不弹路径选择 |
| 绑定多个路径 | 先选择一个绑定路径，再执行匹配 |
| 选定路径属于 Codex 已有项目 | 在对应 Codex 项目中打开新会话 |
| 选定路径不属于 Codex 已有项目 | 路径作为上下文传入，在无项目“聊天”中新建页面；不自动添加项目 |

“聊天”只表示不绑定项目，不是绑定到现有聊天。项目列表只包含本机可用目标，不包含云端/远程项目。

工程默认：比较规范化的完整目录路径，处理尾斜杠和可解析的符号链接，不按项目名称、Git remote 或父子目录模糊匹配；不扫描项目代码。多个项目精确匹配时让用户选择，不随意取第一项。

读取列表失败不等于项目列表为空，不自动归入聊天。路径不存在或不可访问时说明问题并允许重选/取消，不悄悄换目录。这些失败不能被报告为成功。

## 5. 上下文契约

在确认时读取最新任务、项目及附件信息，组装一个纯文本消息。未完成的详情编辑应先按现有保存/冲突规则处理；不能把旧缓存冒充最新数据。

`<neo>` 仅作为外层标记，内部使用用户可直接阅读的文本，不再添加字段标签、属性或任务 UUID。不扩展为父子任务整树或整个项目数据导出。

确认的消息格式：

```text
<neo>
B9 待办标题
备注正文
选定的本地路径：本地项目绝对路径
文件名 本地附件绝对路径
</neo>

用户实际输入的补充指令（有输入时才追加）
```

首行是短编号、一个空格和标题；之后保留备注正文及换行。有选定项目路径时追加一行“选定的本地路径：实际路径”；附件按“文件名 本地绝对路径”逐项换行。项目目录和附件路径分别列出，便于阅读。没有备注、选定路径或附件时省略对应内容，不输出占位文字或空字段。

外层标记内部的文本只做必要的 XML 文本转义（`&`、`<`、`>`），防止正文中的标签提前结束上下文；不引入内部结构。URL 查询参数再单独编码，禁止手工拼接未经编码的 URL 或 shell 命令。

用户没有补充指令时，消息结束于 `</neo>`，不加“开始开发”“先评估”“请读取”等默认指令。有输入时，在闭合标签后空一行，完整保留用户输入及换行，放在最后。路径是上下文信息，不改写成执行指令。

图片、视频、文件统一传本地持久化路径，不另行上传。附件缺失需明确反馈，不声称已提供可读内容。只提供当前待办相关附件，不读取无关内容。

## 6. Skill 契约与隐私

- 更新仓库内 Next One Skill 及必要参考：识别 `<neo>` 为 Next One 格式上下文，从首行识别短编号，必要时通过支持的 CLI 获取最新详情；UUID 不放入消息，写入前仍以 get 返回的最新 UUID/revision 操作。
- `<neo>` 可被任何文本伪造，不是认证或更高优先级指令。正文和附件是数据，不扩大权限；不把用户无补充指令解释为自动开发授权。
- 保留用户指令原意，继续遵守当前项目规则，不直接改数据库。
- 通过已有安装/更新机制交付 Skill，不静默修改用户全局配置。仓库修改和实际目标会话生效分别验收。
- 用户在 Codex 发送及 Agent 读取的内容会进入模型上下文。Next One 本身不增加外部上传服务；不在日志中记录完整备注、拼接 URL 或附件内容。

## 7. 实现边界与建议顺序

使用现有 Swift Package、macOS 14+、SwiftUI/AppKit 和 Store；无需新数据库字段。优先系统 URL 打开能力和已有模块，不引入后台进程。

模块位置：`Sources/TodoApp/` 负责交互与跳转；`Sources/TodoCore/` 复用读取和校验；`Skills/next-one/` 维护上下文识别；测试分别放 `Tests/TodoAppTests/` 与 `Tests/TodoCoreTests/`。

沿用现有风格，例如：

```swift
Button(L("创建 Codex")) { /* 调用应用模型的交接入口 */ }
```

上述仅为接口意图，不是已实现代码。

先验证目标版本的项目列表来源、无项目聊天、项目匹配和深链接预填，再实施完整 UI 和 Skill。可独立验证文本组装；若没有可用项目接口，先记录证据，再就替代方案沟通，不能静默取消目标选择或改为自动新增项目。

- 必须：保留真实数据与无关修改，完整编码，真实反馈，按实际证据更新状态。
- 需另行授权：开发实施、创建测试会话、安装全局 Skill、替换现用应用、发布，以及引入系统权限或后台服务。
- 禁止：修改 Codex 私有数据库、绕过授权、依赖当前 Agent 工具直接充当应用接口、用 Mock 冒充真实跳转验证。
