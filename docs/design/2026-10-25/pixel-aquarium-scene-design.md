# 像素鱼缸：空间、遮挡与生命感设计方案

- 日期：2026-10-25
- 状态：详细设计建议已完成；**新版效果尚未制作或验证**
- 所属功能：[pixel-aquarium Spec](../../spec/2026-10-25/pixel-aquarium.md)
- 技术依据：[原生与开源方案比较](../../research/2026-10-25/aquarium-rendering-options.md)
- 本轮授权：分析五张参考、重新设计、查阅公开项目与维护文档。未修改现有原型或原生应用。

## 1. 设计目标

用户已确认：**保留像素风，空间和运动更真实**。真实感落实为可观察的关系：

1. 同一条鱼有时在沉木前，有时在其后；鱼头、身体、尾巴可依次被遮挡。
2. 叶片之间有空隙，可以透过缝隙看见鱼；叶片摆动时遮挡边缘一起变化。
3. 鱼避开石头和木头的实体，能穿过真实存在的缝、拱洞和草间水道。
4. 鱼以身体弯曲、鳍和尾的动作完成游动，速度与转向有惯性。
5. 水面、细叶、宽叶、颗粒分别以不同方式变化，岩石和木头保持稳定。
6. 缸内清澈、光线有来源，近景和远景的尺度/明暗有所区别。

仍然是常驻待办组件。奖励、自然时间寿命等已确认规则以产品 Spec 为唯一来源。本方案不增加喂食、养护、疾病、货币或繁育任务。

## 3. 三套景观提案

三套均保留同一批鱼和相同业务规则，区别在布局、通行与遮挡方式。名称与顺序是建议，未视为用户已确认。旧版“珊瑚浅湾 / 月色石景”保留为历史原型素材，不再作为本轮自然草缸设计的默认方向。

### A. 榕影石庭——建议默认

- 参考图 5 为主，图 2 补充植物层次。
- 左侧约 35% 为榕树/沉木；树冠偏上，树根落在底床。右侧 25% 为一高一低两块斜石，中间与上层留出水域。
- 底部约 16%–22% 为有起伏的草坪和底床。后方少量高草遮住空缝，颜色比前景深。
- 左树根下留一个可通过的小拱，右石后留一条水道；上部有贯通左右的开阔巡游区。
- 观察乐趣：小鱼从树冠阴影中游出；鱼从斜石后先露头再露全身；大鱼走开阔水道，不挤进树根细孔。
- 正常视角保持约 45%–60% 的投影区域可看到游动中的鱼，不把缸填满。

### B. 沉木秘林——遮挡最丰富

- 参考图 3 为主，图 1 提供细叶草，图 2 提供根系。
- 3–5 根粗细不一的木干形成非等距排列，分别位于前、中、后层；一段横向倒木连接下部景物。
- 中央保留弯曲水道；细叶草填在木干背后，前景用一簇阔叶和少量红草形成颜色区别。
- 每个主要木干附近至少有一条绕行路线；不同大小鱼的路线不能完全相同。
- 观察乐趣：两三条同种小鱼松散结伴，经过木干时依次消失，再在下一个间隙出现；前景叶片短暂遮住其中一条的尾巴。
- 远景鱼更小、更低对比，仍保留可识别的色带；避免将背景鱼处理成模糊光点。

### C. 沙洲小屋——轻松、童趣

- 参考图 4 的空间关系，重画原创圆顶/拱形小屋。
- 左下为有开口的小屋，中部为不等高的圆石，右侧为一簇长叶草；白沙改为米白色，避免桌面上一块刺眼亮面。
- 上半部保持连通水域，底部保留沙纹、少量碎石和柔和投影。
- 小屋开口独立于屋顶/墙面；鱼可从开口进入，留半个身体或尾部在外，稍后原路出来。大鱼不会进入尺寸不足的门洞。
- 观察乐趣来自躲藏、探出和绕石，不新增点击喂鱼或收集装饰功能。

## 4. 画面规格与像素风

### 4.1 视角与尺寸

- 固定正面视角，允许少量可见水面厚度和玻璃侧边，镜头不自动摇晃、不随鼠标转动。
- 设计画幅先采用 3:2；建议常驻默认 240×160 pt，设置宽度 180–420 pt。这是下一版候选值，不是已经生效的设置。
- 悬浮外形建议薄边圆角矩形，圆角只处理玻璃外缘；不裁成圆形而丢失树干、底床和水面。最终外形仍可反馈。
- 同一坐标系描述场景，改变窗口大小只改呈现比例，不重新抽鱼、不重置位置或寿命。
- 180 pt 时优先保留鱼的轮廓和主色带，缩减颗粒与细小高光；不能靠鱼变成 2–3 个像素的小点维持数量。

### 4.2 美术统一

- 采用清晰像素簇、有限色阶；岩石、植物、鱼使用相近的像素密度，避免高清照片底图配低分辨率鱼。
- 暗绿/深灰背板，暖白顶部光源；用青绿、黄绿、深绿区分植物层次，少量红褐草作点缀。
- 不把每片叶子做亮边，不对所有鱼加光晕，不叠加全画面的闪烁或呼吸缩放。
- 素材最近邻采样；世界位置连续计算，最终呈现按统一输出像素网格处理。逐档检查像素粗细和边缘跳动，不能只在放大图上验收。
- 空鱼缸也保留水草、水面和底床的生命感，但不放没有真实奖励依据的常驻赠鱼。

## 5. 前后深度与遮挡

### 5.1 空间模型

采用 **2.5D 固定视角场景**：画面为二维像素素材，运动状态包含 x、y 和前后水层。前、中、后三个主要水层通过少量明确的连通区连接。

- x：横向；y：水中高度；depth：离观察者的远近。不能继续用屏幕 y 代替前后深度。
- 每根木干、石头、植物簇都有自己的深度和透明轮廓。复杂沉木拆成前根、中干、后枝，不能做成一个扁平整图。
- 鱼在水层内连续移动；换水层时位置、大小、朝向平滑变化。
- 路线换层点设置在有足够净空的区域，避开鱼身体与硬景轮廓重叠的位置，防止整条鱼突然跳到树干前方。
- 同一节点深度相同时用稳定的绘制次序；不能因为数组重排让鱼/叶片交替闪烁。

简化边界：首版不允许鱼头在一个水层、尾巴在另一个水层跨着实体木干穿过去，也不承诺任意旋转观察。通过合理通道获得可信画面；如果这一约束导致效果不够自然，再评估真正三维。

### 5.2 遮挡如何发生

依次绘制远处景物、远处鱼、中部景物、中部鱼、近处景物、近处鱼，再叠水面/玻璃效果。实际排序按对象深度进行，不把“所有鱼”固定绘制在同一批次。

例如鱼从中层向右游，前层木干覆盖它经过木干的那一部分像素：

| 时刻 | 应看到的画面 |
| --- | --- |
| 接近木干 | 鱼完整可见，头朝游动方向，尾鳍持续摆动 |
| 鱼头经过木干轮廓 | 头被挡住，身体和尾巴仍可见 |
| 身体经过 | 可见部分逐渐缩短，而不是整条鱼降低透明度 |
| 鱼头从右侧露出 | 右侧出现头，左侧可能仍露尾，形成明确的连续穿行 |
| 离开 | 全身再次可见，速度和摆尾相位连续 |

关键规则：

- 不透明树干和岩石完全挡住其后的鱼，不能透出幽灵轮廓。
- 草叶之间保持真实透明孔隙；鱼只在叶片覆盖的像素处被挡住。
- 摇摆植物的纹理与遮挡来自同一变形后的形状，不能植物移动而遮挡还留在旧位置。
- 宽阔叶片允许少量透光，但默认仍遮住鱼身；先用可靠透明轮廓完成，再研究更细的透光效果。
- 玻璃高光不承担实体遮挡；仅轻微改变最终画面的局部亮度。
- 不对整个鱼节点套一个“躲藏淡出”动画来替代遮挡。

### 5.3 遮挡和碰撞分别定义

| 元素 | 能遮挡鱼 | 鱼可以通过哪里 |
| --- | --- | --- |
| 石头、木干 | 实体轮廓不透明 | 其前方或后方水域，以及石头之间的空隙；不能从实体中心穿出 |
| 细叶植物 | 每片叶子的有效轮廓 | 草簇稀疏部分可穿行，茎根密集部分回避 |
| 阔叶植物 | 叶片按轮廓遮挡 | 从叶片上下或前后绕过 |
| 小屋 | 屋顶/墙面遮挡，开口透明 | 只有足够宽的门洞连通内部；不能从封闭墙面离开 |
| 底床、水面、缸壁 | 构成空间边界 | 所有鱼留在水域，尾鳍也不能伸出水线或插进底砂 |

视觉 alpha 不直接等同于每帧像素级碰撞。静态硬景使用简化多边形及其所在水层；植物用软回避区域。通道净空按鱼身体加尾鳍的包络计算，不能只检查鱼的中心点。

### 5.4 防止鱼长期看不见

- 游动循环交替覆盖开阔水域与遮挡区域，不能所有鱼一直走背景暗处。
- 候选调参目标：一次完全遮挡常见持续约 0.5–2 秒，连续完全遮挡超过 4 秒时选择下一条可见路线；不将鱼瞬移出来。
- 只有 1–2 条鱼时，避免它们同时完全隐藏较长时间；主要观察区应经常有鱼出现。
- 上述时间属于演出参数，不修改真实鱼的存活记录，也不伪造额外鱼。

## 6. 鱼的动作与行为

### 6.1 身体动作

- 头部负责引导方向，前半身轻微弯曲，后半身与尾鳍幅度更大；尾部动作比头部滞后。
- 慢游时摆尾幅度小，短暂加速时摆尾加快；减速后保持细微鳍动。
- 转弯以弧线完成，先改变头部朝向，身体跟随；不要到边界后突然镜像。
- 侧面、斜向靠近、斜向远离至少有可区分姿态。不能仅把整条鱼的横向比例压缩到零模拟转身。
- 像素轮廓要稳定，眼睛、主色带和背腹关系在摆动时不能漂移或串色。

### 6.2 行为分类

原型鱼种只是候选，不以价格直接决定运动。视觉尺寸也不等于现实鱼价。

| 行为型 | 适用视觉方向 | 运动特征 |
| --- | --- | --- |
| 小型群游 | 灯鱼一类 | 同种且数量足够时松散结伴，距离近时分离，少量短促游动后滑行 |
| 悠游巡游 | 孔雀鱼、部分中型鱼 | 常在中上层，长弧线，尾鳍存在滞后；偶尔停在草边 |
| 稳重巡游 | 神仙鱼、较大观赏鱼 | 转弯半径较大、速度较慢，走开阔通道，不硬挤小缝 |

表现是为桌面观感设计的简化，不声明已达到各物种的生物学仿真。不能为了表现群游自动复制新鱼；只有同种实际奖励鱼才参与该组。

### 6.3 最简行为流程

巡游 → 选择通道 → 必要时换层 → 短暂穿行/停留 → 返回开阔水域。障碍回避优先于跟随鱼群，鱼群优先于无目的游走；出入缸是短暂专用状态。

建议起始调参：

- 横穿画面约 15–30 秒；小鱼允许 1–2 秒的短促加速。
- 转向约 0.4–1.2 秒，依鱼体大小和速度调整；不每帧随机改目标。
- 同种邻居距离、分离距离用身体长度的倍数表示，换尺寸后仍协调。
- 位置更新与绘制频率解耦；休眠恢复时不积算几小时的运动，直接恢复合法位置及当前寿命。

### 6.4 新鱼入缸与到期

沿用已确认业务规则，仅改展示：

- 新鱼在水面附近的净空入口进入；有短暂气泡，再游到可见中层。入缸不能穿过树冠、岩石或另一条大鱼。
- 入缸期间给新鱼约 2–3 秒的可见机会，再进入正常巡游。队列内多条奖励错开进入，不整缸重置。
- 到期演出继续建议柔和离场，不做惊吓或惩罚。可在净空处淡成少量气泡；这是到期特效，和日常遮挡严格区分。
- 应用关闭期间新增/到期的鱼，下次打开直接呈现当前仍存活集合，不播放漫长历史入缸/死亡队列。
- 切景时使用一次很短的整体过渡，把同一批鱼安置到新景合法位置；不能在两个场景间飞过实体。切景不重抽鱼、不重置寿命。

## 7. 景观的动作

| 层 | 动作 | 不应发生 |
| --- | --- | --- |
| 水线 | 轻微不规则起伏、局部反射变化；小范围出水口扰动可选 | 整个缸像海浪一样起伏 |
| 细叶草 | 根部固定，末端小幅快摆，不同枝簇略有相位差 | 整簇植物绕中心左右摇摆 |
| 长叶草 | 茎根稳定，上半部顺着同一主水流缓慢弯曲 | 所有叶片完全同频、逆着各自方向乱动 |
| 阔叶/榕树 | 仅少量叶梢轻动，树干不动 | 树冠和树干一起伸缩 |
| 光 | 顶光稳定，少量细碎水纹缓慢移动到叶片/石头/底砂上 | 固定几根巨大光柱、整屏频繁明暗呼吸 |
| 颗粒/气泡 | 少量、不等间隔、速度不同；气泡主要出现在合理位置 | 用密集白点把水做成下雪；全画面同步上升 |
| 阴影 | 景物落地接触阴影稳定，近底鱼仅在条件合适时带弱投影 | 每条鱼无论远近都有黑色椭圆阴影 |

同一场景只设置一个主要水流方向和低频强弱变化，再给植物局部相位差。细小动作在最终 240 pt 尺寸可见即可，不以放大抖动换“生动”。

## 8. 素材拆分与制作要求

### 8.1 每个场景的最小资产包

| 资产 | 建议数量 | 说明 |
| --- | --- | --- |
| 空背板与底床 | 各 1 | 不烘焙鱼，不把所有前景植物和木头合并进去 |
| 硬景 | 3–6 个可排序部分 | 树冠/树干/根、前石/后石、门洞/屋顶/墙按需要拆分 |
| 植物簇 | 6–10 组 | 至少细叶、阔叶、草坪三类；根锚点、变形范围明确 |
| 水线/玻璃 | 各 1 | 薄、低对比，遮住的屏幕面积有限 |
| 场景描述 | 1 份 | 元素位置、深度、碰撞、通道、净空入口，和视觉素材同版维护 |

不为每片叶子建一个独立节点；一簇中选择 2–4 个主要摆动部分，兼顾生动程度和绘制开销。

### 8.2 鱼素材

先用两种体型差异明显的鱼完成空间小样，再扩展已定稿的奖励鱼池。两种鱼小样不代表缩减最终三档规则。

建议每种鱼准备：

- 可识别的侧面、向观察者斜转、背向观察者斜转三种关键姿态；左右复用需检查色带与鳍的方向。
- 主体与尾/鳍的合理分区、头部方向、身体轴线、尾根锚点、完整包络。
- 选定一个主要动画方法：少量关键帧与局部网格形变结合；不同时维护两套完整动画系统。
- 固定图集格子、透明留边、统一比例和中心。禁止沿用旧图集“鱼鳍跨格后人工猜裁剪”的制作方式。
- 原图、透明图集、姿态说明、预览和来源记录一起交付。

### 8.3 制作顺序

先灰模空间/通道 → 黑白遮挡轮廓 → 两种鱼动作小样 → 一套完整上色场景 → 第二、第三套景观与完整鱼池。

生成式图像可用于原创视觉草案和资产，但每张图都需检查轮廓、透明通道和拆层对齐；不能把一张漂亮全景图直接视为可动画的完整场景。参考图保留原样，本轮未上传到外部生成服务。

## 9. 原生实现建议与数据边界

推荐 SpriteKit 呈现固定视角像素场景，GameplayKit 提供路径/避障/群游基础，详见技术比较。最小职责如下：

| 部分 | 自己负责 | 复用能力 |
| --- | --- | --- |
| 场景描述 | 深度、轮廓、根锚点、通道、水流、入口 | 系统文件/资源加载 |
| 游动状态 | 鱼种参数、状态切换、换层净空规则 | GKAgent2D、GKGoal、GKObstacleGraph |
| 场景渲染 | 像素采样、素材、深度到绘制顺序映射 | SKScene、SKSpriteNode、局部 Warp/Shader |
| 窗口输入 | 单击、拖动、右键、解锁和完整边界回收 | 现有 FloatingController / AppKit |
| 鱼的持久记录 | 奖励去重、寿命、事务、UI/CLI 一致 | 现有 TodoCore / Store |

### 9.1 场景契约草案

- 场景元素：id、纹理及图集区域、位置/尺寸、深度、根锚点、变形类型、实体碰撞轮廓。
- 每层水域：可游边界、硬景障碍、软回避区域、连通点和允许体型；连通点需要前后两层都有足够净空。
- 鱼种视觉：素材 ID、身体包络、动作参数、可用姿态和建议水域。
- 运行时鱼：稳定奖励 ID、x/y、当前水层、换层进度、朝向/速度、动作相位与临时行为。
- 业务记录仍是独立事实来源；运行时的位置和动作不每帧写入 SQLite。

GKObstacleGraph 生成的是折线路径。用受限转向和路径跟随形成平滑运动，并在拐角检查鱼包络；不能直接圆滑拐点后把鱼的轨迹切进障碍。若下一步进入实体，保留上一个合法位置、减速并重新选择路线，不能向任意方向瞬移修复。

纯二维碰撞只适用于同一水层。位于树干前/后水层的鱼，屏幕投影即使重叠，也不应被错误弹开。植物变形不能带动石头或使原本合法的硬景通道突然封闭。

### 9.2 窗口与设置

- 鱼缸整体仍是清单入口；普通单击展开/收起、拖动移动、右键菜单沿用。首版不让单击某条鱼抢占展开清单操作。
- 锁定时在鱼缸边缘提供小而清楚的锁定标记，保留右键和菜单栏解锁；景观渲染层不接管这些 AppKit 事件。
- 默认贴靠建议：鱼缸下缘一角与清单上缘同侧角相接，清单向下展开。空间不足时重新选择展开方向。鱼缸放大后不覆盖大块清单内容。
- 屏幕边界回收按整个鱼缸矩形计算，不能继续只给 44 pt 球中心留边距。多屏/缩放后的锚点与三个缩放角需重新实机验收。
- 设置只需景观选择、尺寸和暂停动态效果；开发用深度/碰撞显示不放进普通产品流程。
- 任务面板的透明度不应让鱼缸中的鱼同步变透明；若以后要调整鱼缸透明度，独立讨论。

### 9.3 性能与时间

- 建议 30 fps 常驻；窗口真实不可见、屏幕休眠或用户暂停时停止动画。清单收起但鱼缸仍可见时继续游动。
- 自然时间寿命独立于动画计时；暂停、水层隐藏、降低帧率不延长寿命。
- 探索验证覆盖 0、1、10、30、100 条鱼，200 条作压力观察；这些数字是测试规模，**不是鱼数量限制**。
- 初步性能目标：默认尺寸/10 条鱼下稳定 30 fps，场景更新 P95 小于 4 ms；长时运行无持续内存增长。实际预算需在用户硬件上记录，不预先声称通过。
- 优先减少光效分辨率、颗粒和非关键植物更新频率，再调低绘制频率；不能静默删除、合并真实鱼记录或暂停寿命。
- 大量存活鱼时的最终密度/展示策略尚未决定；若全量显示不达预算，列出实测结果再讨论，而不是自行隐藏奖励。
